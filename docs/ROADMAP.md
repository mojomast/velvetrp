# VelvetRP RPG Feature Roadmap

Development persistence uses one current versioned schema with numbered forward-only migrations, the exact pre-grounding tactical-map upgrade to map v2, and the other narrowly recognized exact predecessor upgrades documented in Operations.

This roadmap is the sole owner of current milestone status and remaining scope. It grew from the completed gap analysis in [the historical RPG integration plan](archive/rpg-integration-plan.md) and [the 2026 architecture notes](roleplay-architecture-2026.md). Repository modules live under `server/src/repo/`, shared runtime contracts live under `packages/contracts/src/`, and the checked API inventory contains 180 counted trusted-local RPG HTTP operations plus feature discovery.

All milestones preserve existing roleplay APIs and local-first SQLite operation. Until a separate remote-authentication project supplies verified principals and authorization, RPG HTTP handlers must continue to use the fixed trusted-local `local-owner` principal, bind only to loopback, and must not be represented as safe for remote or multi-user deployment. Mutations use revisions, idempotency keys, atomic repository transactions, structured problems, and authoritative-read reconciliation when delivery leaves commit status unknown.

M1.1-M1.10, trusted-local HTTP milestones M2.1-M2.11, client milestones M3.1-M3.8, and M4.1-M4.6 are complete. Their per-milestone acceptance detail is archived in [the M1–M4 milestone archive](archive/roadmap-milestones-m1-m4.md).

The ordered playability program is deterministically complete: preparation readiness, the reviewed human/AI adventure, and measured campaign memory are delivered. The GM Director now exposes exact no-replay dispatch inspection, and the measured `now`/`current` lexical correction improves development and frozen holdout ranking without privacy, packing, hydration, provider-cost, or schema changes. The optional matched live reading-quality comparison remains undispatched; the prior one-call RouteTok capability probe is the only live evidence. Plan 4 living knowledge is implemented as an immutable `agent_observations` ledger with bounded witness/`told`/faction/town-gossip propagation, trust-gated reads, labeled Director narration, recorded-knowledge quest offers, and a provider-free attribution/privacy/negation evaluator; the plan's clue-source bridge and any first-class faction-reaction command type remain deferred pending narrowly scoped schema migrations, and per-agent belief projection is not claimed. Plan 5 living Director is implemented: ordered 1-3 candidate composition with per-candidate receipts and partial-completion blockers, four closed read-only grounding tools with a capped planning loop, receipt-recorded world time and ambient transition beats with an optional narration question, Plan 4 knowledge in public narration, labeled non-authoritative prior-scene continuity with up to four cast dialogue lines, a provider-free Director candidate-choice oracle plus rubric, and a live playtest harness; browser `e2e/tests/campaign-dm-living.spec.ts` proves transition composition, the question-less transition scene, NPC knowledge attribution, and no paid call on reload. A follow-on client playability phase makes the character-sheet actions, vendor sale, bilateral trades, room detach, actor placement and camp, companion administration, and reviewed encounter generation browser-reachable, each covered by the deterministic E2E gate.

L3 narration-verification and L7 cost-router are now wired in shadow (record-only). The L1 Director battery was **redesigned from measurement**: the single "is this supported?" noul (which conflated legality, relevance, and immediacy and hedged at 0.53–0.73) is replaced by an atomic `progress` noul ("meaningful next step now?") plus a priority `score`, a `hold` noul, and an aggregate `best_candidate` choice. Live shadow data then drove a Director **transition-beat fallback** (a new per-candidate `transition` `noul` for pacing beats, composed after grounded `progress` and a confident `hold` and only when every advertised candidate is pacing); the fixture eval still measures **~39 acted, 100% acceptable, and 100% exact** with a **PROMOTE** gate; and the lane's recommended action threshold is **0.60** (the server default remains **0.75** until applied). A pure `systemOneCalibration.ts` (Platt map, fit on the development split, scored on the held-out split) fixes the model's systematic under-confidence: at the selected **0.60** threshold a `--repeat 10` run acts on 41/60 samples with **100% acceptable and 100% exact accuracy** (a `--repeat 8` run fell to 29 acted, below the 30-sample gate), and the held-out ECE drops from ~0.21 to ~0.005 (Brier to ~0); a uid-decorrelated probe is recorded as a threshold-fragility finding (selected threshold 0.30, calibrated ECE 0.1344 > 0.10). The fitted map is now **wired into the runtime** as a persisted per-lane `confidenceCalibration` setting (`{ a, b }`, identity by default, clamped on write) applied to the confidence each shadow lane records — it never changes which band a decision lands in.
