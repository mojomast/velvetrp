# Exact combat sheet actions

Natural-language combat item references can commit mechanics only through server-generated exact candidates. The provider receives safe item and target labels, a readable consequence, and an opaque candidate ID and digest. It can select only that pair; inventory identities, catalog references, targets, costs, revisions, dice, damage, healing, resistances, and turn advancement remain server-owned.

Player consumable candidates require controller confirmation. The review identifies the item, target, one-action cost, consumed quantity, and expected effect. Approval does not preserve stale authority: execution rederives the authoritative `useConsumable` legal action and rechecks the current combatant, target relation, possession, pinned definition, combat revision, and actor resource revisions in one immediate transaction.

The existing consumable runtime supports exact damage, healing, health/guard/focus resource effects, resistance/vulnerability/immunity adjustment, actor-health mirroring, effect-duration advancement on round wrap, and turn advancement. Unsupported modifiers and other catalog effects produce no candidate. Immutable combat, actor-resource, candidate, provider-binding, execution, and public-receipt evidence make retries and restart recovery replay the committed result without consuming or rolling twice.

Combat powers use a separate encounter-owned composition; the guarded out-of-combat executor remains unchanged and still rejects active-combat health changes. On the controlled actor's turn, the server may advertise exact single-target action-cost powers for automatic catalog damage, catalog healing, or one deterministic self/ally persistent modifier or condition. Execution revalidates the combat revision, source and actor-backed target M1.5/M1.6 revisions, known/prepared identity, current and execution catalog pins, slot or finite-use cost, team/target legality, synchronized HP, and damage resistance/vulnerability/immunity before server RNG. Cost, actor resources/effects, concentration replacement, combatant HP/status, round effects, turn advancement, combat log, combat receipt, and immutable adventure receipt commit in one immediate SQLite transaction.

Providers can select only `candidateId` and `digest`. Controller review names the power, target, one-action cost, finite cost, and bounded consequence. Area or multi-target powers, `single` targets without team semantics, summons, movement, resource grants, instant/arbitrary modifiers, non-action timing, unsupported mixed effects, and enemy power automation are rejected. Catalog damage is an automatic effect because the current power definition contract has no attack-roll or saving-throw semantics; it must not be narrated as a hit roll.
